This page is a decision tool, not a live page. Jon flagged that the site's page titles, tab labels, section sub-headers, chart/table titles and card headers are inconsistent, with no real hierarchy. Each section below shows the current treatment next to candidate alternatives — including the small mono all-caps "kicker" style used in the rendered reports — so a winner can be picked per level rather than applying one style everywhere. Captions list the exact CSS values to transcribe later. To see combinations of all five together on a full mocked-up page (title, tabs, sections, a table and a chart), visit /design/preview.

3. Tab bar font

Now that the core site font is Inter (2026-09-19, see webapp/README.md's font-system section), the in-page tab bar reads a bit plain sitting in the same face as everything else. Real .section-nav / .tab-underline markup below (the exact classes /records uses) with a live picker — five options with real character, each styled (weight/size/case/spacing) for how that font actually wants to be set as a tab label, not just a drop-in font-family swap. Client-side only, not wired to a cookie — refresh to reset. Real labels from /records' tab row.

3b. IBM Plex Mono: tabs only, or unified with section headers

Section headers (.section-title / .card-header -- the small green uppercase labels, e.g. "BEST TEGS") aren't IBM Plex Mono today -- they're var(--font-table) (Inter), styled bold/uppercase/letter-spaced/green. Tabs sit right above them on tabbed pages, so if tabs go IBM Plex Mono and copy that same uppercase-kicker treatment, the two read as the same idiom in two different typefaces. Two ways to avoid that: keep tabs distinct (Option 1), or unify tabs + section headers into one IBM Plex Mono "structural chrome" layer, separate from Inter (content/data) and Lora (identity) -- and echoing the Reports page's existing IBM Plex Mono kicker style.
