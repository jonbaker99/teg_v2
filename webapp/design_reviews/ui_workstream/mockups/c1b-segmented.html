Segmented control — before / after

A segmented control represents mutually exclusive measures — neither option is "on" or "off," both are equally weighted until one is chosen. Today the site uses a binary switch (implying on/off) or a rounded pill group for this same job. .segmented replaces both, on real measures below.

Before

Net / Gross (Leaderboard)

.scale-switch — geometry says binary on/off, but Net and Gross are two equally valid views, not a default and an override.

After

Net / Gross (Leaderboard)

.segmented — both options read as equal weight; the selected one is marked, not "switched on."

Before

Round view / TEG total (Scoring)

.pill-group — rounded pill geometry is shared with round-number navigation and the player roster, so a measure control looks identical to a link to a different resource.

After

Round view / TEG total (Scoring)

Squared geometry, hairline container — visually distinct from pill-shaped navigation.

Before

Count / % (Scoring heatmap)

Hand-rolled active-state JS inline in scoring_heatmap.html — duplicated a third time, independent of the global tab handler.

After

Count / % (Scoring heatmap)

One shared handler (C4) replaces three independent hand-rolled implementations.

Before

Metric row (Player Rankings)

Three or more options still read as a pill row, same shape as navigation pills elsewhere on the page.

After

Metric row (Player Rankings)

Scales past two options without losing the "one shared container" read.
