| 9 | Admin / reports | Generate buttons have no confirmation. A report already in progress is refused with an error only after tapping; a recently generated report is silently regenerated (overwrites it and costs another API run). Wanted: a check before starting: "already generating (started HH:MM, phase X)" for in-progress runs, and "generated at HH:MM, regenerate and overwrite?" for recent ones. Buttons live in `partials/admin_report_panel.html`; status in `webapp/report_generation.py`. | Open |
| 10 | Admin / live round finalise | Finalise is slow: the R1 request took 41s server-side (Railway HTTP log). It runs synchronously in the request: backups, `execute_data_update`, every cache regeneration, then several separate GitHub commits (backup all-scores, backup all-data, data update, registry). Consider running it as a background job with status (like reports) and batching into one commit. Feedback (issue 4) alone won't fix the duration. | Open |
| 11 | Deploy / Railway (**affects production**) | Data-only commits sometimes trigger a full redeploy despite the watch patterns excluding `data/**`. Seen on the test env during finalise (e.g. "Backup of data/all-data.parquet" deployed, while the neighbouring commits were skipped) and on production on 2026-09-29 ("Set up Par/SI for TEG 19 Round 3/4", "Add round metadata for TEG 19 Round 4" all deployed). Pattern: rapid back-to-back commits; cause not confirmed. Impact: the site is unreachable for a while (R2 finalise got 502 "connection dial timeout"), and in-flight background jobs die — report generation included. On tournament day, finalising a round could kill a report that's running. Options: push all finalise writes as one commit; investigate Railway's skip logic; or move the `[skip ci]`-style guard into commit messages if Railway honours one. | Open |
| 12 | Leaderboard / reports (**feature**) | `/leaderboard` has a Report tab, but it links out to `/teg-reports` and is hidden unless the TEG has a newspaper edition, which only completed TEGs have (`webapp/routes/leaderboard.py` docstring). So during a tournament, round reports can't be reached from the leaderboard. Wanted: a Reports tab on `/leaderboard`, shown mid-tournament, listing each round with its report headline (similar to the home page's "Also in this report" headlines, `webapp/routes/contents.py` `_complete_panel` / `get_edition_summary`), each linking through to that round's report. Rounds without a report yet show as pending. | Open |
| 13 | Home page (**will hit production on the day**) | After TEG 19 completed, the home page showed "TEG 19 — Final Results" with dashes for Trophy, Jacket and Spoon, and no final standings; `/leaderboard` was correct. Cause: the home page's honours line reads `data/teg_winners.csv` (`webapp/deps.py` `get_tournament_state`), and nothing writes TEG 19's row on completion. `calculate_and_save_missing_winners` (`teg_analysis/analysis/history.py`) has no callers; `load_cached_winners` fills gaps in memory only. Fix: run the winners update as a cache step in the finalise/data-update pipeline when a TEG completes (and on deletion). Also check why the standings panel didn't render in the complete state; issue 15's crash may be part of it. | Fixed (Batch 1A) |
| 14 | Handicaps (**will hit production on the day**) | `/handicaps` errors once TEG 19 completes: "Cannot convert non-finite values (NA or inf) to integer". Before completion, TEG 19's saved handicaps were shown; after, the page calculates TEG 20 via `get_hc(20)` (`teg_analysis/analysis/handicaps.py`), which crashes. Cause: `handicaps.csv` has HM and GP blank for TEG 18 but `0.0` for TEG 19 (the TEG setup roster writes 0 for non-players), so they get a TEG 19 row but no TEG 18 row, the pivot gives NaN, and `.astype(int)` fails. SN sat out both TEG 18 and 19; the 36-point rule would handle that (a missed TEG counts as its handicap), but TEG setup saved 0 for SN's TEG 19 handicap, so the result is wrong. Past non-playing regulars kept a handicap. Fix: TEG setup keeps a handicap for regulars sitting out, repair SN's TEG 19 row, exclude players with no handicap in either TEG (HM, GP), and never let one player's gap break the whole page. The home page's Next TEG handicap tiles use the same path. | Fixed (Batch 1A) |
| 15 | Home page / Next TEG (**will hit production on the day**) | `KeyError: 'TEGNum'` in `_next_teg_context` (`webapp/routes/contents.py:226`) once the next TEG is TEG 20. With no TEG 20 round_info, it falls back to `get_future_tegs()`, which returns only `TEG, Year, Area` (`teg_analysis/analysis/history.py`), dropping the `TEGNum` column the caller filters on. Never hit before because TEG 19 had round_info. Fix: return `TEGNum` from `get_future_tegs`, and show TBC when there's no row at all (future_tegs.csv has no TEG 20). | Fixed (Batch 1A) |
| 16 | Home page (**will hit production on the day**) | The final standings table on the home page only appears once the tournament report exists. `webapp/templates/partials/_contents_complete_view.html` branches on `state.report_summary`: with a report it loads the `/contents/panel?state=complete` standings; without one it shows the older "— Final Results" block with the three winner names and a Full Results button, and no standings. The panel partial (`_contents_panel.html`) already handles a missing report (single column), so the fix is to always load the standings panel and show the headlines column only when a report exists. Winner names still depend on issue 13. | Fixed (Batch 1A) |
